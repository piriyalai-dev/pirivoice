# บทที่ 19 การเลื่อนชั้นนักเรียนทั้งโรงเรียน

การเลื่อนชั้นนักเรียนทั้งโรงเรียนเป็นงานที่ดำเนินการปีละครั้ง เพื่อย้ายสมาชิกทั้งโรงเรียนเข้าสู่ปีการศึกษาใหม่ในครั้งเดียว ตั้งแต่การสร้างปีปลายทาง การดูแผนเลื่อนชั้น การแก้ไขห้องที่ระบบไม่สามารถจับคู่ได้เอง ไปจนถึงการกดยืนยัน งานนี้ย้อนกลับไม่ได้ ผู้ปฏิบัติงานจึงต้องอ่านแผนให้ครบถ้วนก่อนกดยืนยันทุกครั้ง

ความสามารถหลักของระบบเลื่อนชั้นมีดังนี้

1. **การดูแผนก่อน:** ระบบแสดงแผนให้ดูก่อนเสมอ ยังไม่เขียนข้อมูลใดจนกว่าผู้ปฏิบัติงานจะยืนยัน
2. **การเลือกห้องด้วยตนเอง:** ห้องที่ระบบจับคู่ให้ไม่ได้ ระบบไม่เดาแทน ผู้ปฏิบัติงานต้องเลือกเอง
3. **การเขียนครั้งเดียว:** เมื่อกดยืนยันแล้วทั้งโรงเรียนถูกเขียนพร้อมกัน หากขั้นตอนใดล้มเหลว จะไม่มีข้อมูลใดถูกเขียนเลย

## 19.1 กลุ่มผู้ใช้งานและขอบเขตของบท

ผู้ที่มีสิทธิ์จัดการข้อมูลนักเรียนและมีขอบเขตระดับโรงเรียนคือผู้ดูแลระบบ ครูสภานักเรียน และประธานสภา ส่วน ครูทั่วไป ประธานระดับ สภานักเรียน และผู้ช่วยหัวหน้าระดับจะไม่เห็นเมนูนี้ แม้จะแก้ไขข้อมูลนักเรียนรายคนได้ตามปกติ เนื่องจากการเลื่อนชั้นเปลี่ยนสถานะสมาชิกทุกระดับพร้อมกัน

ก่อนเริ่มดำเนินการ ผู้ปฏิบัติงานเตรียมสามสิ่งให้ครบถ้วน ได้แก่ ปีการศึกษาปัจจุบันที่โรงเรียนใช้อยู่และมีสมาชิกในปีนั้น ปีปลายทางที่ยังว่างซึ่งต้องสร้างไว้ที่หน้า **“ปีการศึกษา”** ก่อนหากยังไม่มี และห้องปลายทางของทุกระดับชั้น ทั้งนี้ควรปิดงานที่ค้างและแก้ไขรายชื่อให้เรียบร้อยก่อน หากโรงเรียนยังใช้ระบบอยู่ ควรทำนอกเวลาเรียน เนื่องจากเมื่อกดยืนยันระบบจะหยุดรับการแก้ไขตารางสมาชิกชั่วครู่

## 19.2 การเตรียมปีปลายทางก่อน

ก่อนเลื่อนชั้น ผู้ปฏิบัติงานสร้างปีการศึกษาและห้องของปีปลายทางให้พร้อมตามขั้นตอนต่อไปนี้

**เส้นทางการเข้าถึงเมนู**

1. เปิด **“ปีการศึกษา”** ผ่านแท็บ **“เพิ่มเติม”** กลุ่ม **“โรงเรียน”** แล้วเลือก **“ปีการศึกษา”**
2. ที่การ์ด **“ขั้นต่อไปของการขึ้นปีใหม่”** กด **“สร้างปีการศึกษาใหม่”**
3. กรอก **“ปีการศึกษา (พ.ศ.)”** พร้อมวันเปิดและวันปิดภาคเรียน แล้วบันทึก
4. กลับมาดูรายการปี เพื่อให้แน่ใจว่าปียังไม่ถูกกด **“ใช้เป็นปีปัจจุบัน”** เนื่องจากขั้นตอนนี้ยังไม่ต้องกด
5. สร้างห้องของปีใหม่ให้ครบ หรือปล่อยให้ระบบสร้างตอนนำเข้ารายชื่อก็ได้

การ์ด **“ขั้นต่อไปของการขึ้นปีใหม่”** เตือนลำดับงานหกขั้น ได้แก่ การสร้างปี การเลื่อนชั้นทั้งโรงเรียน การนำเข้ารายชื่อด้วย Excel การตรวจกระทบยอดรายชื่อ การตั้งภาคเรียนของปีใหม่ และการมอบหมายเรื่องที่ผู้รับหมดวาระ ระบบไม่ได้บังคับลำดับด้วยโปรแกรม แต่หากข้ามขั้นตอนใดไปจะต้องไล่แก้ไขภายหลัง

ระบบอ่านเฉพาะปีที่ยังไม่มีสมาชิก หากปีปลายทางมีนักเรียนอยู่แล้วแม้คนเดียว ระบบจะไม่ยอมดำเนินการ เพราะจะกลายเป็นการนำรายชื่อสองชุดมาทับกันโดยไม่มีผู้ใดทราบ หากระบบยังมีปีการศึกษาไม่ถึงสองปี หน้าเลื่อนชั้นจะยังไม่สามารถทำอะไรได้ และแสดงข้อความแจ้งเตือน ดังแสดงในภาพที่ 19.1

![ภาพที่ 19.1 หน้าเลื่อนชั้นเมื่อยังมีปีการศึกษาไม่ถึงสองปี](../../../docs/assets/screenshots/staff/student-promote.webp)
**ภาพที่ 19.1** แสดงหน้าเลื่อนชั้นเมื่อยังมีปีการศึกษาไม่ถึงสองปี พร้อมข้อความแจ้ง ปุ่มไปยังหน้าปีการศึกษา และแถบประวัติการเลื่อนชั้น

จากภาพที่ 19.1 ส่วนประกอบและปุ่มคำสั่งที่ทำเครื่องหมายหมายเลขกำกับไว้ มีรายละเอียดการทำงานดังนี้

1. ข้อความ **“ยังมีปีการศึกษาไม่ถึง 2 ปี”** เป็นข้อความแจ้งเตือนว่าขณะนี้ระบบยังไม่สามารถเลื่อนชั้นได้ ระบบจะแสดงข้อความนี้จนกว่าจะสร้างปีการศึกษาครบสองปี
2. ปุ่มไปยังหน้า **“ปีการศึกษา”** ใช้เปิดหน้าจัดการปีการศึกษา เมื่อกดปุ่ม ระบบจะนำผู้ปฏิบัติงานไปยังหน้าที่ใช้สร้างปีการศึกษาใหม่
3. แถบ **“ประวัติการเลื่อนชั้น”** ใช้เปิดรายการประวัติการเลื่อนชั้นรอบก่อนหน้า เมื่อกดแถบ ระบบจะแสดงรายการรอบที่เคยดูแผนหรือยืนยันไว้

## 19.3 การดูแผนเลื่อนชั้น

เมื่อเตรียมปีปลายทางแล้ว ผู้ปฏิบัติงานเปิดแผนเลื่อนชั้นเพื่อตรวจสอบว่าระบบจะดำเนินการอย่างไรตามขั้นตอนต่อไปนี้

**เส้นทางการเข้าถึงเมนู**

1. เปิดแท็บ **“เพิ่มเติม”**
2. เลือกกลุ่ม **“โรงเรียน”**
3. เลือก **“เลื่อนชั้นนักเรียน”**

**ลำดับขั้นตอนการปฏิบัติงาน**

1. ตรวจสอบช่อง **“ปีต้นทาง”** ซึ่งระบบเลือกปีปัจจุบันให้แล้ว พร้อมข้อความกำกับ **“(ต้องเป็นปีปัจจุบัน)”**
2. เลือก **“ปีปลายทาง”** เป็นปีใหม่ โดยตัวเลือกจะแสดงจำนวนสมาชิกของแต่ละปีให้เห็น
3. กด **“ดูแผน”** แล้วอ่านแผนจากบนลงล่าง

แผนเลื่อนชั้นประกอบด้วยส่วนต่าง ๆ ที่ต้องอ่านให้ครบถ้วน ดังแสดงในตารางที่ 19.1

**ตารางที่ 19.1** แสดงส่วนประกอบของแผนเลื่อนชั้นและข้อมูลที่ต้องอ่าน

| ส่วนของแผน | ข้อมูลที่ต้องอ่าน |
|---|---|
| **“ต้องแก้ก่อน (N ข้อ)”** | สีแดง ซึ่งยังกดยืนยันไม่ได้จนกว่าจะแก้ครบ |
| **“ควรตรวจก่อน (N ข้อ)”** | สีเหลือง ซึ่งดำเนินการได้ แต่ควรอ่านก่อน |
| การ์ดสรุป | **“สมาชิกปีนี้”** **“เลื่อนขึ้นปีใหม่”** และ **“จบการศึกษา”** |
| รายการหมายเหตุ | บุคลากรที่ยกไป ตำแหน่งที่ถูกกำหนดกลับเป็นนักเรียน สภานักเรียนที่สิ้นสุดวาระ และนักเรียนที่ไม่มีห้อง |
| **“ต้องเลือกห้องปลายทางเอง (N ห้อง)”** | ห้องที่ระบบจับคู่ให้ไม่ได้ |
| ตารางต่อระดับชั้น | คู่ห้องต้นทางและห้องปลายทาง พร้อมจำนวนคน |
| จบการศึกษา | รายชื่อห้อง ม.6 และจำนวนคน |

ผู้ปฏิบัติงานกด **“ดูแผน”** ซ้ำได้ไม่จำกัด เนื่องจากไม่แก้ไขข้อมูลใด แต่ทุกครั้งจะเกิดแถวประวัติหนึ่งรายการไว้สำหรับย้อนดูว่าระบบประเมินอะไรไว้ในขณะนั้น

## 19.4 ความหมายของแผนเลื่อนชั้น

ระบบจัดระดับชั้นปลายทางตามรหัสห้อง เช่น ห้องที่ขึ้นต้น ม.1/ จะไปยัง ม.2/ และห้อง ม.6/ ถือว่าสำเร็จการศึกษา หากรหัสห้องไม่ตรงกับรูปแบบที่ระบบรู้จัก ระบบจะไม่เดาและปล่อยห้องนั้นไว้ให้ผู้ปฏิบัติงานเลือกเอง

การ์ดสรุปมีตัวเลขสามรายการที่ต้องตรงกับที่โรงเรียนคาดไว้ ได้แก่ **“สมาชิกปีนี้”** ซึ่งเป็นจำนวนแถวที่ใช้งานอยู่ทั้งหมดในปีต้นทาง **“เลื่อนขึ้นปีใหม่”** ซึ่งเป็นจำนวนคนที่จะได้แถวใหม่ในปีปลายทาง และ **“จบการศึกษา”** ซึ่งเป็นจำนวนคนห้อง ม.6 ที่จะไม่ได้รับแถวใหม่

รายการหมายเหตุใต้การ์ดบอกว่าแผนจะดำเนินการกับแต่ละกลุ่มดังนี้

1. **การยกบุคลากรไปปีใหม่:** ครูทั่วไป ผู้ดูแลระบบ และตำแหน่งระดับโรงเรียนยกไปทั้งบทบาทและสิทธิ์เดิม
2. **การกำหนดตำแหน่งในห้องเป็นนักเรียนธรรมดา:** หัวหน้าห้องและรองฝ่ายทุกคนต้องแต่งตั้งใหม่หลังขึ้นปีการศึกษา
3. **การสิ้นสุดวาระของสมาชิกสภานักเรียน:** ตำแหน่งสภาต้องเลือกตั้งใหม่ ระบบไม่ยกให้
4. **นักเรียนที่ไม่มีห้อง:** นักเรียนที่ยังไม่มีห้องจะถูกยกไปโดยไม่มีห้อง ต้องไปกำหนดห้องภายหลัง

## 19.5 การเลือกห้องปลายทางที่ระบบจับคู่ไม่ได้

กรณีที่รหัสห้องต้นทางเลื่อนขึ้นระดับถัดไปไม่ได้ เช่น ชื่อห้องไม่ตรงรูปแบบ หรือเป็นห้องของระดับชั้นที่ไม่มีระดับถัดไป ระบบจะให้ผู้ปฏิบัติงานเลือกห้องปลายทางเองตามขั้นตอนต่อไปนี้

**ลำดับขั้นตอนการปฏิบัติงาน**

1. อ่านกล่อง **“ต้องเลือกห้องปลายทางเอง (N ห้อง)”** ซึ่งบอกชื่อห้อง จำนวนคน และเหตุผล
2. เลือก **“ห้องปลายทาง”** ให้ครบทุกห้อง
3. กด **“ดูแผนอีกครั้ง”**
4. ตรวจสอบว่ากล่องสีแดงหายไป และปุ่มยืนยันกดได้แล้ว

**ผลลัพธ์การทำงานของระบบ**

ระบบไม่เดาแทน เพราะการเดาผิดจะทำให้นักเรียนทั้งห้องไปอยู่ผิดที่โดยไม่มีผู้ใดทราบ ระหว่างแก้ไขช่องห้อง จะมีแถบ **“แก้ห้องปลายทางแล้ว”** แจ้งว่าแผนที่เห็นอยู่ยังไม่รวมค่าล่าสุด และปุ่มยืนยันถูกล็อกไว้จนกว่าจะกด **“ดูแผนใหม่”**

ห้องปลายทางต้องมีอยู่จริงในระบบ ระบบไม่สร้างห้องใหม่ให้ตอนเลื่อนชั้น

## 19.6 การแก้ไขข้อที่ต้องแก้ก่อน

ข้อที่ทำให้กดยืนยันไม่ได้มีห้าประเภท ซึ่งระบบเขียนไว้ในกล่อง **“ต้องแก้ก่อน”** โดยตรง ดังนี้

1. ปีต้นทางกับปีปลายทางเป็นปีเดียวกัน ต้องเป็นคนละปี ให้เลือกปีปลายทางเป็นปีอื่น
2. ปีต้นทางไม่ใช่ปีปัจจุบัน ให้ตั้งปีนั้นเป็นปีปัจจุบันก่อน หรือเลือกปีปัจจุบันเป็นปีต้นทาง
3. ปีที่ระบุไม่มีสมาชิกที่ใช้งานอยู่ ให้ตรวจสอบว่านำเข้ารายชื่อของปีนั้นแล้วหรือยัง
4. มีนักเรียนในห้องที่หาห้องปลายทางไม่ได้ ให้เลือกห้องปลายทางให้ครบแล้วดูแผนใหม่
5. มีเลขประจำตัวนักเรียนซ้ำกันในห้องปลายทางเดียวกัน ให้แก้ไขเลขที่ซ้ำในห้องต้นทางก่อน ซึ่งมักเกิดเมื่อเลือกห้องปลายทางให้สองห้องรวมเป็นห้องเดียว

นอกจากนี้ เมื่อกดยืนยัน ระบบอาจแจ้งว่าปีปลายทางมีสมาชิกอยู่แล้ว ซึ่งหมายความว่ามีผู้ใช้งานนำเข้ารายชื่อแทรกเข้ามาหลังจากดูแผน ระบบจะยกเลิกทั้งงานและไม่เขียนข้อมูลใด ให้ลบสมาชิกในปีนั้นหรือเลือกปีอื่น

## 19.7 การยืนยันเลื่อนชั้น

เมื่อแผนถูกต้องครบถ้วนแล้ว ผู้ปฏิบัติงานยืนยันการเลื่อนชั้นตามขั้นตอนต่อไปนี้

**ลำดับขั้นตอนการปฏิบัติงาน**

1. ตรวจสอบว่าปุ่ม **“ยืนยันเลื่อนชั้นทั้งโรงเรียน”** กดได้ และข้อความใต้ปุ่มแจ้งว่าย้อนกลับเองไม่ได้ ระบบจะเขียนสมาชิกทั้งโรงเรียนในครั้งเดียว
2. กดปุ่มยืนยัน
3. อ่านข้อความยืนยันซึ่งสรุปจำนวนคนที่จะยก จำนวนที่สำเร็จการศึกษา จำนวนบุคลากร และปีที่จะกลายเป็นปีปัจจุบัน
4. กด **“ยืนยัน เลื่อนชั้น”**

> **ข้อควรระวังสำคัญ:** งานนี้ย้อนกลับจากหน้าจอไม่ได้ หากพลาด ทางเดียวคือกู้ฐานข้อมูลจากไฟล์สำรอง ผู้ปฏิบัติงานควรอ่านตัวเลขในหน้าแผนเทียบกับที่โรงเรียนคาดไว้ให้ตรงก่อนกดทุกครั้ง

**ผลลัพธ์การทำงานของระบบ**

หลังสำเร็จ ระบบจะแสดงข้อความ **“เลื่อนชั้นเรียบร้อย”** พร้อมบรรทัดสรุป เช่น **“เลื่อนขึ้นปีใหม่ 812 คน จบการศึกษา 210 คน บุคลากร 34 คน และปิดแถวปีเก่า 1,056 แถว”** พร้อมแจ้งว่าปีการศึกษาที่ระบุเป็นปีปัจจุบันแล้ว จากนั้นหน้าจะโหลดปีใหม่กับประวัติรอบใหม่ให้ทันที

การเปลี่ยนสถานะของการเลื่อนชั้นตลอดวงจรชีวิตแสดงเป็นแผนผังได้ดังนี้

> **[แทรกภาพที่ 19.2: แผนผังสถานะของการเลื่อนชั้น]**
**ภาพที่ 19.2** แสดงแผนผังสถานะของการเลื่อนชั้น

แผนผังแสดงการเปลี่ยนสถานะตั้งแต่เข้าสู่สถานะยังไม่ได้ดูแผน จากนั้นเมื่อกด **“ดูแผน”** หากพบข้อที่ต้องแก้ ระบบจะเข้าสู่สถานะต้องแก้ก่อน แต่หากเงื่อนไขครบถ้วนจะเข้าสู่สถานะพร้อมยืนยัน เมื่อกดยืนยันและระบบเขียนสำเร็จ งานจะเข้าสู่สถานะทำแล้ว แต่หากมีผู้ใช้งานนำเข้ารายชื่อแทรกเข้ามา หรือปีใหม่ไม่มีผู้ดูแลระบบ ระบบจะยกเลิกทั้งงาน เส้นทางการเปลี่ยนสถานะทั้งหมดตามแผนผังปรากฏดังแสดงในตารางที่ 19.2

**ตารางที่ 19.2** แสดงเส้นทางการเปลี่ยนสถานะของการเลื่อนชั้นตามแผนผัง

| ลำดับ | จากสถานะ | ไปยังสถานะ | เงื่อนไข |
|---|---|---|---|
| 1 | เริ่มต้น | ยังไม่ได้ดูแผน | เปิดเมนูเลื่อนชั้นนักเรียน |
| 2 | ยังไม่ได้ดูแผน | ต้องแก้ก่อน | กดดูแผน แล้วพบข้อที่ต้องแก้ |
| 3 | ยังไม่ได้ดูแผน | พร้อมยืนยัน | กดดูแผน แล้วเงื่อนไขครบถ้วน |
| 4 | ต้องแก้ก่อน | ต้องแก้ก่อน | เลือกห้องปลายทาง แล้วดูแผนใหม่ |
| 5 | พร้อมยืนยัน | ต้องแก้ก่อน | แก้ไขช่องห้องหลังดูแผน |
| 6 | พร้อมยืนยัน | ทำแล้ว | กดยืนยัน แล้วระบบเขียนสำเร็จ |
| 7 | พร้อมยืนยัน | ยกเลิกทั้งงาน | มีผู้ใช้งานนำเข้ารายชื่อแทรก หรือปีใหม่ไม่มีผู้ดูแลระบบ |
| 8 | ทำแล้ว | สิ้นสุด | ปิดกระบวนการ |

รอบเลื่อนชั้นมีสามสถานะ ได้แก่ **“ดูแผนแล้ว”** **“ทำแล้ว”** และ **“ล้มเหลว”** รอบที่ขึ้นว่า **“ทำแล้ว”** ใช้ซ้ำไม่ได้ ระบบจะตอบว่า **“รอบการเลื่อนชั้นนี้ถูกใช้ไปแล้ว”** พร้อมแนะนำให้กดดูแผนใหม่เพื่อดูสถานะปัจจุบันก่อนตัดสินใจอีกครั้ง

## 19.8 การดูประวัติการเลื่อนชั้น

ผู้ปฏิบัติงานตรวจสอบประวัติการเลื่อนชั้นตามขั้นตอนต่อไปนี้

**เส้นทางการเข้าถึงเมนู**

1. เลือก **“เลื่อนชั้นนักเรียน”**
2. เปิดแถบ **“ประวัติการเลื่อนชั้น”** ที่ท้ายหน้า

**ผลลัพธ์การทำงานของระบบ**

ป้ายสถานะมีสามแบบ ได้แก่ **“ทำแล้ว”** **“ล้มเหลว”** และ **“ดูแผนไว้”** โดยป้าย **“ดูแผนไว้”** หมายความว่าเคยกดดูแผนแต่ยังไม่ยืนยัน จึงไม่มีข้อมูลใดถูกแก้ไข หน้าแสดงประวัติยี่สิบรอบล่าสุด และโหลดข้อมูลเมื่อกางออกเท่านั้น

## 19.9 การทำงานเบื้องหลังของระบบ

ระบบเลื่อนชั้นดำเนินการเบื้องหลังเพื่อให้การเขียนข้อมูลเป็นไปอย่างปลอดภัยและครบถ้วน ดังนี้

1. เมื่อยืนยันแล้ว ระบบเขียนข้อมูลทั้งหมดในครั้งเดียว หากขั้นตอนใดล้มเหลวจะไม่มีข้อมูลใดถูกเขียน จึงไม่ต้องกู้คืน
2. ระบบล็อกงานด้วยกลไกป้องกันการทำงานซ้ำซ้อน ผู้ใช้งานกดพร้อมกันกี่คนก็ได้ผลลัพธ์เดียว และผู้ที่แพ้จะได้รับข้อความว่ารอบถูกใช้ไปแล้ว
3. ขั้นแรก ระบบยกบุคลากรไปปีใหม่พร้อมบทบาท ห้อง สิทธิ์ และหน้าที่เดิม
4. ขั้นถัดมา ระบบสร้างแถวใหม่ให้แก่ผู้ที่เลื่อนขึ้น โดยทุกคนได้รับตำแหน่ง **“นักเรียน”** และสิทธิ์ของนักเรียน
5. เลขที่ในห้องยกไปตามเดิมโดยตั้งใจ เนื่องจากยังไม่ทราบเลขที่ของห้องใหม่ ให้ไฟล์ Excel ของปีใหม่ปรับปรุงทับภายหลัง
6. แถวเดิมของปีเก่าถูกปิดเป็นสถานะเลื่อนชั้นแล้ว ส่วนห้อง ม.6 ถูกปิดเป็นสถานะสำเร็จการศึกษาแล้ว และไม่สร้างแถวใหม่
7. หากปีใหม่ไม่เหลือผู้ดูแลระบบเลย ระบบยกเลิกทั้งงาน เนื่องจากสิทธิ์ทั้งระบบอ่านจากตารางสมาชิกของปีปัจจุบัน
8. ระบบตั้งปีปลายทางเป็นปีปัจจุบัน และเปลี่ยนค่าเริ่มต้นของปีการศึกษาในตารางสมาชิกให้ชี้ไปยังปีใหม่
9. นักเรียนที่ไม่มีห้องถูกยกไปด้วยโดยไม่มีห้อง ไม่หายจากระบบ
10. ครูทั่วไป ที่สังกัดห้อง ม.6 ถูกยกไปปีใหม่ ไม่สำเร็จการศึกษา และระบบเตือนไว้ในกล่องที่ควรตรวจก่อน
11. ทุกครั้งที่ดูแผน ระบบบันทึกประวัติการดูแผนเลื่อนชั้น ส่วนการยืนยันบันทึกประวัติการยืนยันเลื่อนชั้น พร้อมจำนวนทุกประเภท
12. ระบบไม่แจ้งเตือนนักเรียนเมื่อเลื่อนชั้น

## 19.10 ข้อจำกัดและข้อควรระวัง

การเลื่อนชั้นมีข้อจำกัดและข้อควรระวังที่ควรทราบ ดังนี้

1. ย้อนกลับไม่ได้จากหน้าจอ ต้องกู้จากไฟล์สำรองฐานข้อมูลเท่านั้น
2. ทำได้เฉพาะปีที่ตั้งเป็นปีปัจจุบัน หากจะย้อนทำปีเก่า ต้องตั้งปีนั้นเป็นปีปัจจุบันก่อน
3. ปีปลายทางต้องว่าง ระบบไม่ยอมเขียนทับรายชื่อที่มีอยู่
4. ไม่สามารถยกเลิกระหว่างทำงานได้ และไม่สามารถตั้งเวลาให้ทำล่วงหน้าได้
5. การกดดูแผนทุกครั้งเกิดแถวประวัติเพิ่มขึ้น แม้ไม่ได้ยืนยัน
6. ไม่สามารถส่งออกรายชื่อก่อนและหลังเลื่อนชั้นเป็นไฟล์ได้
7. ระบบไม่สร้างห้องปลายทางให้ ต้องมีห้องอยู่ก่อน
8. เลขที่ในห้องไม่ถูกจับคู่ใหม่ตามระดับชั้น ต้องแก้ไขด้วยการนำเข้า Excel ของปีใหม่
9. นักเรียนที่สำเร็จการศึกษาแล้วเข้าสู่ระบบไม่ได้ แต่ประวัติและเรื่องที่เคยแจ้งยังคงอยู่ และค้นชื่อได้ด้วยการค้นข้ามปี

## 19.11 แนวทางการแก้ไขปัญหาที่พบบ่อยในการใช้งาน

ในระหว่างการเลื่อนชั้น ผู้ปฏิบัติงานอาจพบปัญหาที่พบบ่อย ซึ่งมีแนวทางการแก้ไขสรุปไว้ในตารางที่ 19.3

**ตารางที่ 19.3** แสดงแนวทางการแก้ไขปัญหาที่พบบ่อยในการใช้งานระบบเลื่อนชั้น

| ปัญหาหรือสถานการณ์ที่พบ | สาเหตุและแนวทางการแก้ไข |
|---|---|
| เข้าหน้าเลื่อนชั้นไม่ได้ หรือระบบแจ้งว่าเฉพาะส่วนกลาง | บัญชีต้องมีสิทธิ์จัดการข้อมูลนักเรียนและมีตำแหน่งระดับโรงเรียน คือผู้ดูแลระบบ ครูสภานักเรียน หรือประธานสภา ครูประจำชั้นและประธานระดับจัดการรายคนได้ แต่เลื่อนชั้นทั้งโรงเรียนไม่ได้ |
| กดดูแผนแล้วระบบแจ้งว่าปีต้นทางไม่ใช่ปีปัจจุบัน | ระบบบังคับให้เริ่มจากปีที่โรงเรียนใช้อยู่ ให้ไปที่ **“ปีการศึกษา”** ตั้งปีที่ต้องการเป็นปีปัจจุบันก่อน แล้วกลับมาดูแผนใหม่ |
| ปุ่มยืนยันกดไม่ได้ แต่ไม่เห็นข้อความสีแดง | ตรวจสอบว่ากด **“ดูแผน”** แล้วหรือยัง และได้แก้ไขช่องห้องปลายทางหลังดูแผนหรือไม่ หากแก้ไขแล้วต้องกด **“ดูแผนใหม่”** เสมอ ระบบจึงจะตรวจสอบเงื่อนไขใหม่ทั้งชุด |
| ห้องหนึ่งไม่มีคู่ปลายทาง ระบบจะเดาให้หรือไม่ | ระบบไม่เดา แต่จะแสดงห้องนั้นในกล่อง **“ต้องเลือกห้องปลายทางเอง”** พร้อมจำนวนคนและเหตุผล ให้เลือกให้ครบแล้วกดดูแผนอีกครั้ง |
| กดยืนยันแล้วระบบแจ้งว่าปีปลายทางมีสมาชิกอยู่แล้ว | มีผู้ใช้งานนำเข้ารายชื่อเข้าปีปลายทางหลังจากดูแผน ระบบยกเลิกทั้งงานและไม่มีข้อมูลใดถูกแก้ไข ให้ตรวจสอบปีปลายทาง ลบรายชื่อที่แทรกเข้ามา หรือเลือกปีอื่น แล้วดูแผนใหม่ |
| กดยืนยันแล้วระบบแจ้งว่าปีใหม่จะไม่มีผู้ดูแลระบบ | บุคลากรที่มีสิทธิ์ผู้ดูแลระบบในปีต้นทางไม่ได้ถูกยกไป หรือถูกถอดสิทธิ์ก่อนเลื่อนชั้น ระบบยกเลิกทั้งงานเพื่อไม่ให้โรงเรียนล็อกตนเอง ให้เพิ่มผู้ดูแลระบบในปีปลายทางหรือยกบุคลากรให้ครบแล้วทำใหม่ |
| หลังเลื่อนชั้นแล้วนักเรียนเข้าสู่ระบบไม่ได้ | ตรวจสอบว่าบัญชีนั้นเป็นห้อง ม.6 ที่สำเร็จการศึกษาแล้ว หรือแถวเดิมถูกปิดเป็นสถานะเลื่อนชั้นแล้วโดยไม่มีแถวใหม่ ให้ค้นชื่อด้วยการค้นข้ามปีในหน้า **“สมาชิก”** เพื่อดูสถานะแต่ละปี |
| ทำผิดแล้วต้องการย้อนกลับ | หน้าจอไม่มีปุ่มย้อนกลับ ต้องติดต่อผู้ดูแลระบบเพื่อกู้ฐานข้อมูลจากไฟล์สำรองรอบล่าสุด หรือแก้ไขด้วยตนเองทีละคน แต่ต้องตรวจสอบรายชื่อทั้งโรงเรียนเอง |
| ดูแผนซ้ำหลายรอบแล้ว ประวัติจะรกหรือไม่ | ทุกรอบถูกบันทึกโดยตั้งใจ เพื่อเป็นหลักฐานว่าระบบประเมินอะไรไว้ในขณะนั้น ประวัติที่ขึ้น **“ดูแผนไว้”** ยืนยันได้ว่าไม่มีข้อมูลใดถูกแก้ไขในรอบนั้น |
