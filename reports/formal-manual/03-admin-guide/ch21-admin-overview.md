# บทที่ 21 ภาพรวมการใช้งานของผู้ดูแลระบบ

คู่มือภาคนี้จัดทำขึ้นสำหรับผู้ที่รับผิดชอบดูแลโครงสร้างของระบบทั้งโรงเรียน ได้แก่ การจัดการปีการศึกษาและภาคเรียน การกำหนดตำแหน่งและสิทธิ์ของสมาชิก การตั้งค่าที่มีผลต่อผู้ใช้งานทั้งโรงเรียน ตลอดจนการตรวจสอบย้อนหลังเมื่อข้อมูลสูญหายหรือเกิดการแก้ไขที่ผิดปกติ ผู้ปฏิบัติงานในภาคนี้จึงต้องเข้าใจภาพรวมของระบบก่อนลงมือจัดการส่วนใดส่วนหนึ่ง เพื่อให้การดำเนินการแต่ละครั้งถูกต้องครบถ้วน และไม่ส่งผลกระทบต่อผู้ใช้งานรายอื่นโดยไม่ได้ตั้งใจ

ความสามารถหลักของผู้ดูแลระบบที่ครอบคลุมไว้ในคู่มือภาคนี้ มีดังนี้

1. **ปีการศึกษาและภาคเรียน:** การตั้งปีการศึกษาปัจจุบัน การสร้างภาคเรียน และการสั่งเปิดหรือปิดภาคเรียน
2. **สมาชิกและสิทธิ์:** การเพิ่มผู้ใช้งาน การตั้งตำแหน่ง และการกำหนดหน้าที่ความรับผิดชอบ
3. **บันทึกการใช้งาน:** การตรวจสอบว่าใครแก้ไขข้อมูลใด เมื่อใด และผลการดำเนินการเป็นอย่างไร
4. **แดชบอร์ดและรายงาน:** การดูภาพรวมและสุขภาพของระบบจากสถิติการใช้งานต่าง ๆ

ภาพเปิดของคู่มือภาคนี้คือแดชบอร์ดของผู้ดูแลระบบ ซึ่งตัวเลขทุกใบอ่านได้ทั้งในภาพรวมทั้งโรงเรียนและเฉพาะระดับชั้น ขึ้นอยู่กับป้ายขอบเขตที่มุมขวาบนของหน้าจอ ดังแสดงในภาพที่ 21.1

![ภาพที่ 21.1 แดชบอร์ดภาพรวมทั้งโรงเรียน](../../../docs/assets/screenshots/admin/dashboard-overview.webp)
**ภาพที่ 21.1** แสดงแดชบอร์ดภาพรวมทั้งโรงเรียน ซึ่งประกอบด้วยป้ายขอบเขต การ์ดสรุปจำนวนเรื่อง และแถบคำอธิบายสีใต้การ์ด

จากภาพที่ 21.1 ส่วนประกอบและปุ่มคำสั่งที่ทำเครื่องหมายหมายเลขกำกับไว้ มีรายละเอียดการทำงานดังนี้

1. ป้ายขอบเขต **“ภาพรวมทั้งโรงเรียน”** อยู่ที่มุมขวาบนของหน้าจอ ใช้กำหนดขอบเขตการอ่านตัวเลขทั้งหมดว่าดูในภาพรวมทั้งโรงเรียนหรือเฉพาะระดับชั้นใดระดับชั้นหนึ่ง
2. การ์ด **“เรื่องทั้งหมด”** แสดงจำนวนเรื่องทั้งหมดที่อยู่ในขอบเขตที่เลือกไว้
3. การ์ด **“รอรับเรื่อง”** แสดงจำนวนเรื่องที่ยังอยู่ระหว่างรอผู้รับเรื่อง
4. การ์ด **“งานเกินเวลา”** แสดงจำนวนงานที่เลยกำหนดเวลาไปแล้ว
5. แถบคำอธิบายสีใต้การ์ด แสดงความหมายของสีที่ใช้กำกับป้ายสถานะต่าง ๆ เพื่อให้อ่านผลได้โดยไม่สับสน

## 21.1 กลุ่มผู้ใช้งานและขอบเขตของบท

ผู้ที่ใช้คู่มือภาคนี้ได้แบ่งตามตำแหน่งและสิทธิ์พื้นฐาน โดยตำแหน่งที่มีสถานะผู้ดูแลระบบจะใช้งานได้ครบทุกบท ส่วนตำแหน่งที่ไม่มีสถานะผู้ดูแลระบบจะเห็นเฉพาะแดชบอร์ดในขอบเขตระดับชั้นของตนเอง และต้องได้รับสิทธิ์เพิ่มเติมจึงจะใช้งานบทอื่นได้ ดังแสดงในตารางที่ 21.1

**ตารางที่ 21.1** แสดงตำแหน่งที่มีสิทธิ์ใช้คู่มือภาคนี้พร้อมสิทธิ์พื้นฐานและขอบเขตงาน

| ตำแหน่ง | สิทธิ์พื้นฐาน | งานในภาคนี้ |
|---|---|---|
| ผู้ดูแลระบบ | เป็นผู้ดูแลระบบ | ทำได้ทุกบท |
| ครูสภานักเรียน | เป็นผู้ดูแลระบบ | ทำได้ทุกบท |
| ประธานสภา | เป็นผู้ดูแลระบบ | ทำได้ทุกบท |
| ครูทั่วไป | ไม่เป็นผู้ดูแลระบบ | เห็นแดชบอร์ดเฉพาะระดับชั้นของตนเอง ส่วนบทอื่นต้องมีสิทธิ์เพิ่มเติม |

สถานะผู้ดูแลระบบเป็นค่าที่ทำให้ผู้ใช้งานข้ามการตรวจสอบสิทธิ์รายข้อทั้งหมด ระบบอ่านค่าสถานะนี้จากตำแหน่งในไฟล์กำหนดบทบาทของระบบทุกครั้งที่มีการเปลี่ยนตำแหน่ง จึงไม่มีปุ่มตั้งสถานะผู้ดูแลระบบแยกจากตำแหน่งบนหน้าจอ

บัญชีผู้ดูแลระบบสูงสุดที่กำหนดไว้ในตัวแปรของระบบก็ข้ามการตรวจสอบสิทธิ์เช่นเดียวกัน ใช้เมื่อต้องกู้ระบบในกรณีที่ไม่มีผู้ดูแลระบบคนใดเข้าสู่ระบบได้

## 21.2 สิทธิ์ที่เกี่ยวข้องกับภาคนี้

สิทธิ์หลักที่ผู้ดูแลระบบใช้ในคู่มือภาคนี้แบ่งเป็นสี่รายการ โดยแต่ละสิทธิ์ใช้กับงานและบทที่แตกต่างกัน ดังแสดงในตารางที่ 21.2

**ตารางที่ 21.2** แสดงสิทธิ์หลักของผู้ดูแลระบบพร้อมการใช้งานและบทที่เกี่ยวข้อง

| สิทธิ์ | ใช้ทำอะไร | บท |
|---|---|---|
| สิทธิ์จัดการข้อมูลนักเรียน | เพิ่มและแก้ไขสมาชิก กำหนดตำแหน่ง | บทที่ 22 |
| สิทธิ์ดูบันทึกการใช้งาน | เปิดบันทึกการใช้งาน | บทที่ 23 |
| สิทธิ์จัดการการตั้งค่า | ตั้งปีการศึกษา ภาคเรียน และช่วงเวลาแจ้งเตือน | บทที่ 25 และบทที่ 24 |
| สิทธิ์เปิดแดชบอร์ด | เปิดแดชบอร์ดและสถิติการใช้งาน | บทที่ 26 |

การดูบันทึกการใช้งานต้องมีขอบเขตข้อมูลระดับทั้งโรงเรียนเท่านั้น ครูทั่วไป แม้ได้รับสิทธิ์ดูบันทึกการใช้งานแล้วก็ยังถูกปฏิเสธ เนื่องจากเห็นข้อมูลได้เฉพาะระดับชั้นที่ตนเองดูแล

## 21.3 การเริ่มต้นใช้งานในวันแรก

เมื่อเริ่มใช้งานระบบ ผู้ปฏิบัติงานควรตรวจสอบความพร้อมของข้อมูลพื้นฐานตามลำดับต่อไปนี้ เพื่อให้แน่ใจว่าระบบพร้อมใช้งานและข้อมูลตรงกับสภาพจริงของโรงเรียน

**ลำดับขั้นตอนการปฏิบัติงาน**

1. เข้าสู่ระบบด้วยบัญชีผู้ดูแล แล้วเปิดแท็บ **“เพิ่มเติม”** ตรวจสอบว่ามีเมนูครบถ้วน
2. เปิด **“ปีการศึกษา”** ตรวจสอบว่ามีปีปัจจุบันตรงกับปีที่โรงเรียนใช้อยู่จริง
3. เปิด **“ภาคเรียน”** ตรวจสอบว่ามีภาคเรียนปัจจุบันและช่วงวันที่ตรงกับปฏิทินโรงเรียน
4. เปิด **“สมาชิก”** ตรวจสอบว่ามีผู้ดูแลระบบอย่างน้อยหนึ่งคนในปีการศึกษานี้
5. เปิด **“ตั้งค่าการแจ้งเตือน”** ที่หน้าโปรไฟล์ แล้วตั้งช่วงเวลาเงียบหากต้องการ
6. เปิด **“แดชบอร์ด”** แล้วเทียบตัวเลขนักเรียนและห้องกับความจริง

## 21.4 การเลือกบทตามลักษณะงาน

เมื่อทราบลักษณะของงานแล้ว ผู้ปฏิบัติงานเลือกเปิดบทที่ตรงกับงานนั้นได้ตามตารางที่ 21.3

**ตารางที่ 21.3** แสดงการเลือกบทตามลักษณะงานที่ต้องการดำเนินการ

| หากต้องการ | อ่านบท |
|---|---|
| ตั้งหัวหน้าห้องคนใหม่ เพิ่มผู้ใช้งานทีละคน หรือให้หน้าที่เฉพาะทาง | บทที่ 22 |
| สืบว่าใครแก้ไขข้อมูลใด เมื่อใด และแก้ไขไม่ได้เพราะเหตุใด | บทที่ 23 |
| สร้างปีการศึกษา ตั้งปีปัจจุบัน หรือตั้งภาคเรียน | บทที่ 25 |
| ปรับช่วงเวลาไม่ส่งแจ้งเตือน หรือดูค่าที่กระทบทั้งระบบ | บทที่ 24 |
| อ่านสถิติเรื่อง สถิติการเข้าใช้งาน หรือตรวจสุขภาพระบบ | บทที่ 26 |
| ตอบคำถามทางเทคนิคเรื่องชื่อสิทธิ์ ชื่อตาราง หรือค่าสถานะ | บทที่ 27 |

งานที่เกี่ยวกับข้อมูลนักเรียนรายคน การนำเข้าไฟล์ Excel การเลื่อนชั้น และการมอบหมายเรื่อง อยู่ในคู่มือเจ้าหน้าที่และสภานักเรียนในภาคที่ 2 ซึ่งผู้ดูแลระบบก็ใช้ได้เช่นเดียวกัน

## 21.5 ตำแหน่งของเมนูผู้ดูแลระบบ

เมนูทั้งหมดของผู้ดูแลระบบอยู่ในแท็บ **“เพิ่มเติม”** โดยแบ่งเป็นสองกลุ่ม ดังนี้

1. กลุ่ม **“ผู้ดูแล”** ประกอบด้วยเมนู **“แดชบอร์ด”** **“จัดการรายงาน”** **“สมาชิก”** และ **“ย้ายห้องนักเรียน”**
2. กลุ่ม **“โรงเรียน”** ประกอบด้วยเมนู **“จัดการประกาศ”** **“ปีการศึกษา”** **“เลื่อนชั้นนักเรียน”** **“กระทบยอดรายชื่อ”** **“ภาคเรียน”** **“เรื่องที่ผู้รับหมดวาระ”** และ **“บันทึกการใช้งาน”**

ส่วนเมนู **“เจ้าหน้าที่”** และ **“นำเข้านักเรียน”** ไม่ได้อยู่ในเมนูหลัก ผู้ปฏิบัติงานเข้าได้จากแท็บและปุ่มในหน้า **“สมาชิก”** และเมนู **“จัดการกิจกรรม”** อยู่ในแท็บ **“จัดการ”** ของหน้า **“กิจกรรม”**

## 21.6 หลักปฏิบัติเพื่อความปลอดภัย

การดูแลระบบต้องยึดหลักปฏิบัติเพื่อความปลอดภัยต่อไปนี้ เพื่อให้ข้อมูลถูกต้องและตรวจสอบย้อนหลังได้เสมอ

1. ทุกการเพิ่ม แก้ไข และลบข้อมูลสำคัญถูกบันทึกใน **“บันทึกการใช้งาน”** พร้อมผู้ดำเนินการ เวลา และค่าเดิมกับค่าใหม่
2. ไม่มีหน้าจอใดให้แก้ไขหรือลบบันทึกการใช้งาน หากต้องการปิดร่องรอยต้องดำเนินการที่ฐานข้อมูลเท่านั้น
3. การเปลี่ยนปีปัจจุบันเปลี่ยนค่าเริ่มต้นของปีการศึกษาของสมาชิกใหม่ทันที จึงต้องทำนอกเวลาใช้งาน
4. การลบในระบบนี้เป็นการซ่อนข้อมูล ข้อมูลยังคงอยู่และกู้คืนได้ ยกเว้นกรณีที่ระบุไว้เป็นอย่างอื่น
5. เก็บรหัสผ่านและไฟล์สำรองฐานข้อมูลให้พ้นจากเครื่องที่นักเรียนเข้าถึงได้

> **ข้อควรระวังสำคัญ:** มีสี่งานที่ย้อนกลับจากหน้าจอไม่ได้ ได้แก่ การยืนยันเลื่อนชั้นทั้งโรงเรียนซึ่งสมาชิกทั้งโรงเรียนถูกเขียนใหม่ในครั้งเดียวและกู้คืนได้เฉพาะจากไฟล์สำรอง การปิดเรื่องซึ่งเปิดใหม่จากหน้าจอไม่ได้ต้องแก้ที่ฐานข้อมูล การลบปีหรือภาคเรียนซึ่งซ่อนจากรายการแต่กด **“กู้คืน”** ในแท็บ **“ถูกลบ”** ได้ และการเปลี่ยนตำแหน่งสมาชิกซึ่งสิทธิ์เปลี่ยนทันทีและแถวของปีเก่าไม่เปลี่ยนตาม

## 21.7 แนวทางการแก้ไขปัญหาที่พบบ่อยในการใช้งาน

ในระหว่างการใช้งานคู่มือภาคนี้ ผู้ปฏิบัติงานอาจพบปัญหาที่พบบ่อย ซึ่งมีแนวทางการแก้ไขสรุปไว้ในตารางที่ 21.4

**ตารางที่ 21.4** แสดงแนวทางการแก้ไขปัญหาที่พบบ่อยในการใช้งานระบบสำหรับผู้ดูแล

| ปัญหาหรือสถานการณ์ที่พบ | สาเหตุและแนวทางการแก้ไข |
|---|---|
| เมนูบางรายการไม่แสดงผลทั้งที่เป็นผู้ดูแลระบบ | เมนูถูกกรองด้วยสิทธิ์ของบัญชี และบัญชีต้องมีแถวสมาชิกที่ใช้งานในปีปัจจุบันด้วย ให้ตรวจที่หน้า **“สมาชิก”** ว่าบัญชีมีแถวในปีนี้และยังเป็นผู้ดูแลระบบอยู่ |
| เปลี่ยนตำแหน่งแล้วสิทธิ์ไม่เปลี่ยนทันที | ระบบอ่านสิทธิ์จากแถวสมาชิกทุกครั้งที่เรียกใช้งาน ไม่ได้เก็บไว้ในเว็บเบราว์เซอร์ หากหน้าจอยังแสดงเมนูเดิม ให้โหลดหน้าจอใหม่หรือออกจากระบบแล้วเข้าสู่ระบบใหม่อีกครั้ง |
| มีผู้ดูแลระบบได้กี่คน | ระบบไม่จำกัดจำนวนผู้ดูแลระบบ แต่ต้องเหลืออย่างน้อยหนึ่งคนในปีปัจจุบันเสมอ หากเลื่อนชั้นแล้วปีใหม่ไม่มีผู้ดูแลระบบเลย ระบบจะยกเลิกการเลื่อนชั้นทั้งงานให้โดยอัตโนมัติ |
| ผู้ดูแลระบบตั้งค่ารหัสผ่านใหม่ให้นักเรียนได้หรือไม่ | หน้าจอไม่มีฟังก์ชันนี้ นักเรียนเปลี่ยนรหัสผ่านด้วยตนเองที่หน้าโปรไฟล์ หากลืมรหัสผ่านจริง ต้องให้ผู้พัฒนาตั้งรหัสผ่านใหม่ที่ฐานข้อมูล |
| เห็นข้อมูลนักเรียนไม่ครบทั้งโรงเรียน | บัญชีอาจผูกกับระดับชั้น เช่น ครูทั่วไป หรือประธานระดับ ผู้ที่เห็นข้อมูลทั้งโรงเรียนคือผู้ดูแลระบบ ครูสภานักเรียน ประธานสภา และตำแหน่งที่มีขอบเขตข้อมูลระดับทั้งโรงเรียน |
| ต้องการย้อนดูว่าใครแก้ไขข้อมูลใดก่อนเกิดปัญหา เริ่มจากที่ใด | เปิด **“บันทึกการใช้งาน”** แล้วกรองตามช่วงวันที่และชื่อผู้ใช้งาน หากไม่ทราบว่าเป็นผู้ใด ให้กรองตามชนิดข้อมูล แล้วอ่านค่าเดิมและค่าใหม่ของรายการที่ใกล้เวลาที่เกิดเหตุ |
