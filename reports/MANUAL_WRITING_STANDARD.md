## 1. บทบาท เป้าหมาย และหลักความจริงสูงสุด

ผู้เรียบเรียงทำหน้าที่เป็นนักวิชาการและนักเขียนเอกสารคู่มือเทคนิคอาวุโส ผู้เชี่ยวชาญ
การจัดทำรายงานราชการและคู่มือการปฏิบัติงานมาตรฐานของสถานศึกษาไทย

**กฎเหล็กสูงสุด 4 ข้อ:**

1. **ห้ามแค่ Find & Replace คำผิด และห้ามแปลคำต่อคำ:** ต้องกลับไปอ่านไฟล์ต้นฉบับ `.md`
   ใน `docs/` ของบทนั้นใหม่ทุกครั้ง ตกผลึกข้อเท็จจริงทั้งหมด แล้ว **เรียบเรียงใหม่ทั้งบท**
   ด้วยสำนวนเอกสารราชการที่สละสลวย ยาว ละเอียด ครบถ้วน และท้าวความเชื่อมโยงเหตุ-ผล
   ตั้งแต่ต้นจนจบทุกย่อหน้า
2. **ยึดไฟล์ใน `docs/` เป็นความจริงสูงสุด 100%:** อ่านเฉพาะ **บทที่ 4 และบทที่ 7**
   จาก `~/reports/pirivoice-manual-draft-2026-11-26.html` เพื่อดูต้นแบบน้ำหนักภาษา
   โครงสร้างประโยค และความละเอียดเท่านั้น **ห้ามคัดลอกข้อเท็จจริงที่ล้าสมัยหรือข้อผิดพลาด
   จากไฟล์ร่างมาใช้** (เช่น ฟีเจอร์อัปโหลดรูปภาพใหม่, คำผิด “การส่งองงาน”, ตัวสะกด
   “IPhone”, หรือคำว่า “รีเฟรช”)
3. **ครบถ้วน 100% ห้ามย่อ ห้ามตัด ห้ามข้าม:** อธิบายทุกปุ่ม ทุกเมนู ทุกชิปตัวกรอง
   ทุกสถานะ ทุกเงื่อนไข และทุกคำถามท้ายบทให้ครบทุกประการ
4. **ทำงานเป็นชุด (Batch):** ตามแผนในส่วนที่ 6 และรันสคริปต์ตรวจคุณภาพ
   `reports/lint_manual.py` ทุกครั้ง เพื่อให้คุณภาพบทท้ายละเอียดเท่าบทแรก

## 3. มาตรฐานศิลปะการเรียบเรียงภาษาทางการ

### 3.1 หลักการท้าวความและขยายความ
- **เปิดบท (`# บทที่ X`):** ความเรียง 1 ย่อหน้าเต็มมีน้ำหนัก → ประโยคนำ → รายการลำดับตัวเลข
  (`1.`, `2.`, `3.`…) 3–4 ข้อ ขึ้นต้นด้วยหัวข้อตัวหนา+โคลอน (ห้ามขึ้นต้นบทด้วยประโยคคำถามแบบบล็อก)
- **เปิดหัวข้อหลัก (`## X.Y`) และย่อย (`### X.Y.Z`):** มีอย่างน้อย 1 ย่อหน้าท้าวความก่อนขึ้น
  ขั้นตอน/ภาพ/ตารางเสมอ
- **ทุกย่อหน้าสมบูรณ์ตั้งแต่ต้นจนจบ:** ใช้ประโยคความรวม/ความซ้อนมีเหตุผลชัดเจน
  หลีกเลี่ยง Passive Voice เยิ่นเย้อ และห้ามขึ้นต้นย่อหน้าติดต่อกันด้วยคำเชื่อมซ้ำ
  (*นอกจากนี้, ทั้งนี้, อย่างไรก็ตาม, ในส่วนของ*)

### 3.2 ตัวอย่างระดับภาษา (ห้ามเขียน / ต้องเขียน)
- ❌ `เมื่อรับเรื่องเข้ามาแล้ว เจ้าหน้าที่ต้องดำเนินการในลำดับใดบ้าง บทนี้อธิบาย...`
- ✅ `เมื่อนักเรียนส่งเรื่องร้องเรียนหรือข้อเสนอแนะเข้าสู่ระบบ PIRIvoice แล้ว การบริหารจัดการ
  เรื่องของคณะกรรมการห้องเรียน ประธานระดับ และคณะกรรมการสภานักเรียนถือเป็นกลไกสำคัญ...`
- การตอบคำถามในตารางแก้ไขปัญหา: ตอบเต็มประโยคสุภาพ เช่น ❌ `ไม่ เมื่อตั้งรหัสผ่านใหม่สำเร็จแล้ว...`
  → ✅ `ระบบจะไม่บังคับให้ผู้ใช้งานเปลี่ยนรหัสผ่านซ้ำในทุกครั้งที่เข้าสู่ระบบ...`
- การอธิบายหมายเลขกำกับบนภาพ (ส่วนแสดงผลที่กดไม่ได้): ห้ามเขียน “เมื่อกดแล้วไม่เกิดอะไรขึ้น”
  ให้อธิบายความหมาย/เงื่อนไขที่ระบบนำมาแสดงผลแทน

## 5. มาตรฐานโครงสร้าง Markdown เพื่อรองรับ `.odt`

### 5.1 ระดับหัวข้อ (3 ระดับเท่านั้น ไม่มี YAML frontmatter)
- `# บทที่ X ชื่อบท` · `## X.1 หัวข้อหลัก` · `### X.1.1 หัวข้อย่อย`
- ห้ามใช้ `#/##/###/####` กับป้ายกำกับขั้นตอนและกล่องหมายเหตุ (ใช้ตัวหนาเดี่ยวหรือ blockquote แทน)

### 5.2 รูปภาพ คำบรรยายภาพ (ใต้ภาพ) และรายการอธิบายหมายเลข
1. ประโยคนำก่อนภาพลงท้าย “ดังแสดงในภาพที่ X.Y”
2. ภาพจริงใน `docs/assets/screenshots/` → ลิงก์ `../../../docs/assets/screenshots/...` + บรรทัด
   `**ภาพที่ X.Y** แสดง...` **ใต้ภาพทันที**
3. แผนผัง Mermaid → แท็ก `> **[แทรกภาพที่ X.Y: ...]**` + `**ภาพที่ X.Y** แสดง...` ใต้แท็กทันที
   + ตารางอธิบายเส้นทาง/เงื่อนไขครบทุกกิ่ง
4. รายการอธิบายหมายเลข: ขึ้นต้นด้วย “จากภาพที่ X.Y ส่วนประกอบและปุ่มคำสั่งที่ทำเครื่องหมาย
   หมายเลขกำกับไว้ มีรายละเอียดการทำงานดังนี้” แล้วเขียนเป็นรายการลำดับตัวเลข `1.`, `2.`, `3.`
   เสมอ (ส่วนที่กดได้อธิบาย 3 มิติ: ชื่อ/ตำแหน่ง + หน้าที่ + ผลลัพธ์; ส่วนแสดงผลอธิบายตำแหน่ง +
   ความหมาย/เงื่อนไข)
5. เลขลำดับ `ภาพที่ X.1, X.2, ...` เรียงต่อเนื่องไม่ข้ามไม่ซ้ำ

### 5.3 ตารางและคำบรรยายตาราง (อยู่ “เหนือตาราง”)
1. ประโยคนำอ้างอิงเลขตารางก่อนตารางเสมอ (“...ดังแสดงในตารางที่ X.Y”)
2. ชื่อตาราง `**ตารางที่ X.Y** แสดง...` วาง **เหนือตารางทันที**
3. ข้อความในเซลล์เป็นภาษาทางการเต็มรูป (ห้ามคำห้วน `ขึ้น/ไม่ขึ้น` → `แสดงผล/ไม่แสดงผล`)
4. หัวข้อท้ายบท: `## X.Y แนวทางการแก้ไขปัญหาที่พบบ่อยในการใช้งาน` + ประโยคนำ + ชื่อตารางเหนือตาราง
   + ตาราง 2 คอลัมน์ (`ปัญหาหรือสถานการณ์ที่พบ` | `สาเหตุและแนวทางการแก้ไข`) ครบทุกคำถาม
5. เลขลำดับ `ตารางที่ X.1, X.2, ...` เรียงต่อเนื่องไม่ข้ามไม่ซ้ำ

### 5.4 โครงสร้างขั้นตอน 4 ส่วน + รายการตัวเลข
- ใช้รายการตัวเลข `1.` แทนขีด `-` เป็นหลัก โดยขึ้นต้นรายการสรุปด้วยหัวข้อย่อยตัวหนา+โคลอน
- ทุกหัวข้อที่กดทำรายการในระบบต้องมีครบ 4 ส่วนเรียงตามลำดับ (ชื่อหัวข้อตัวหนาขึ้นบรรทัดเดี่ยว):
  1. `**เส้นทางการเข้าถึงเมนู**` + รายการตัวเลข (1. 2. 3. …) — **ห้ามใช้ลูกศร `→` เรียงขั้นตอนต่อกันในบรรทัดเดียว** ให้แยกเป็นข้อ ๆ
  2. `**สิ่งที่ต้องเตรียมหรือเงื่อนไขก่อนดำเนินการ**` + ย่อหน้า
  3. `**ลำดับขั้นตอนการปฏิบัติงาน**` + รายการตัวเลข (โยงหมายเลขภาพ เช่น “(หมายเลข 1 ในภาพที่ 3.4)”)
  4. `**ผลลัพธ์การทำงานของระบบ**` + ย่อหน้า
- ล้าง syntax VitePress 100%: `::: tip/warning/danger` → blockquote (`> **ข้อแนะนำในการใช้งาน:**` /
  `> **ข้อควรระวังสำคัญ:**`), mermaid → แท็กแทรกภาพ, HTML tag → ลบ, ลิงก์ `./xxx` →
  ข้อความอ้างอิงภาษาไทย (“ดังรายละเอียดในบทที่ 3”)
